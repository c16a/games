# Add 2048 to Happy Arcade

## Goal

Add a polished, kid-friendly version of 2048 to Happy Arcade. The game must run entirely in the browser, work well with touch and keyboard input, and load only when the player opens it.

## Player experience

- Add a **2048** card to the game picker with a **Numbers** badge and a cheerful description.
- Opening the card starts a playable 4 × 4 number grid.
- Players combine matching tiles by swiping up, down, left, or right.
- Support the arrow keys and WASD as keyboard alternatives.
- Begin each game with two tiles. After every move that changes the board, add one new tile in an empty cell.
- New tiles should normally be 2, with a small chance of being 4.
- Show the current score and the best score for this device.
- Persist only the best score in `localStorage`; do not add accounts or remote storage.
- Include **New game** and **Undo** controls. Undo should restore only the immediately previous valid move and may be used once per move.
- Celebrate when the player first creates the 2048 tile and let them either keep playing or start again.
- Show a friendly game-over result when no legal moves remain.

## Rules

- A move slides every tile as far as possible in the chosen direction.
- Two adjacent tiles with the same value merge into one tile worth twice as much.
- A tile created by a merge cannot merge again during the same move.
- Add the value of every newly merged tile to the score.
- A move that does not change the board must not add a tile, change the score, or consume the undo state.
- The game is won when a 2048 tile is created, but play may continue beyond 2048.

## Interface and accessibility

- Match Happy Arcade’s playful visual language while giving the number tiles clear contrast and distinct value styling.
- Keep the full board and primary controls usable without horizontal scrolling at widths down to 320px.
- Prevent page scrolling while a swipe starts and ends inside the board, without blocking normal vertical page scrolling elsewhere.
- Use semantic buttons with accessible names and visible focus states.
- Give the board an accessible label and announce score changes, wins, and game over with an appropriate live region.
- Do not rely on tile color alone: every tile must display its number.
- Respect `prefers-reduced-motion`; sliding and merge animations must become effectively instant when requested.

## Architecture

- Put the game in `src/games/2048/`.
- Export the `GameModule` lifecycle from `src/games/2048/index.ts` and remove all listeners, timers, and animation resources in `destroy()`.
- Keep the game engine-free and use semantic HTML, CSS, and TypeScript.
- Add 2048 to the catalogue and dynamic loader in `src/main.ts`; do not import it eagerly.
- Keep board movement, merging, score calculation, legal-move detection, and tile spawning as testable logic separate from DOM rendering.
- Use injectable randomness in game logic so tile spawning can be tested deterministically.
- Do not add dependencies.

## Tests

Add focused Bun tests covering at least:

1. Sliding tiles through empty cells.
2. A single merge, including its score.
3. Multiple independent merges in one row, such as `2 2 2 2` becoming `4 4`.
4. The rule that a merged tile cannot merge twice in one move, such as `2 2 4` becoming `4 4`, not `8`.
5. All four movement directions.
6. No tile spawn after an unchanged move.
7. Deterministic spawning into an empty cell.
8. Correct detection of playable and game-over boards.
9. Detection of the first 2048 tile.
10. Undo restoring the previous board and score.

## Acceptance criteria

- A player can open 2048 from the picker, play a complete game using touch or keyboard, undo a move, restart, win, continue after winning, and reach game over.
- Navigation back to the picker works and leaves no active event listeners or timers behind.
- Existing games continue to load and play independently.
- `bun test` passes.
- `bun run build` passes.
